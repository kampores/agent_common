# 7.5. 推論結果および例外処理

[LLM マニュアル一覧](01_unified_llm_client_jp.md)

> 設定の準備と最小限の呼び出しについては、まず [7.1 モデルプロファイル管理およびテキスト生成](01_model_profiles_and_generation_jp.md) を参照してください。

## 1. 戻り値と例外処理

| 状況 | 動作 | 確認項目 |
| :--- | :--- | :--- |
| モデルプロファイル未登録 | コンストラクタで `LlmInferenceError` | `llm_pool` キー名およびモデル選択設定 |
| 非サポートの provider | `LlmInferenceError` | `auto`, `external`, `local` のいずれかであるか確認 |
| 外部サービス無効化・API キー欠落 | 外部パスで `None` 返却 | 有効化設定と認証環境変数 |
| HTTP・URL 通信エラー | `LlmInferenceError` | サーバー応答、アドレス、認証、ネットワーク |
| 必須レスポンスフィールド欠落 | `LlmInferenceError` | 標準/Fabrix 形式と実際のレスポンス構造 |
| ローカルファイル未存在 | `None` 返却 | プロジェクトルート基準のファイルパス |
| ローカルライブラリ未インストール | モデルファイル存在時に `LlmInferenceError` | 実行環境の依存パッケージ導入状況 |
| JSON パース、数値変換、一部タイムアウト・モデル実行エラー | 元の例外が送出される可能性あり | `LlmInferenceError` だけで全失敗を捕捉できると過信しない |

呼び出し元アプリケーションは `None` と例外を明確に区別して処理する必要があります。タスク境界において明示的な例外を優先捕捉し、最後に予期せぬ例外を処理して後続処理を継続するか判断します。例外ログの出力には `ProjectLogger` の `logger.exception` を使用します。
